# Authorization Service

## Overview
Это приложение - домашнее задание для ИТ-лагеря Т1. Приложение реализует сервис авторизации, который позволяет пользователям регистрироваться и авторизовываться. Приложение использует token-based аутентификацию с использованием JWT (JSON Web Tokens).

## Requirements
- Java 21 or higher
- Docker

## Setup
1. Поднимите сервис PostgreSQL с помощью Docker из директории проекта:
```
docker-compose up -d
```
2. Запустите приложение (не в докере, просто с локальной машины).

## Usage
1. После того как приложение запустится, стоит подождать еще +- 5 секунд, пока не появится надпись `Инициализация ролей завершена`.
2. После окончательной загрузки приложения можно перейти в папку scratchers и запустить ендпоинты с регистрацией заранее подготовленных пользователей:
- Endpoint 1: `POST http://localhost:8080/api/register`
  - Эта ручка отправляет данные в формате JSON для регистрации пользователя с полями:
```json
{
  "login": "login",
  "email": "email@example.com",
  "password": "password",
  "role": ["guest | premium_user | admin"]
}
```
3. После успешной регистрации можно авторизоваться. Для этого можно перейти в файл `api-tests.http` и запустить ендпоинты или выполнить запрос к такой ручке:
- Endpoint 2: `POST http://localhost:8080/api/login`
  - Эта ручка отправляет данные в формате JSON для авторизации пользователя с полями:
```json
{
  "login": "login",
  "password": "password"
}
```
4. После успешной авторизации вы получите JWT токен, который нужно будет использовать для доступа к защищенным ресурсам приложения. Токен нужно в ручную добавить в переменные для токенов в файле `api-tests.http`.
Токен живет всего 30 минут после того, как произошел логин. Если Произойдет повторный логин, то старый токен станет недействительным, и нужно будет использовать новый токен.
5. После того как вы получили токен, можно перейти к защищенным ресурсам приложения. Для этого можно использовать файл `api-tests.http`, где уже есть примеры запросов к защищенным ресурсам с использованием токена:
- Endpoint 3: `GET http://localhost:8080/api/access/guest`
  - Эта ручка защищена и требует авторизации. Токен нужно передать в заголовке запроса:
```Authorization
  Bearer <your token>
```
Точно так же работают и остальные ручки, для доступа к premium и admin ролям:
- Endpoint 4: `GET http://localhost:8080/api/access/premium`
- Endpoint 5: `GET http://localhost:8080/api/access/admin`

6. В приложении реализована ручка проверки прав токена, которая выведет информацию о том, что доступно конкретному пользователю:
- Endpoint 6: `GET http://localhost:8080/api/access/check`
```Authorization
  Bearer <your token>
```
7. Токен можно отозвать вручную. Для этого можно использовать ручку:
- Endpoint 7: `POST http://localhost:8080/api/revoke-token`
```Authorization
  Bearer <your token>
```

## Testing
Как говорилось выше, в проекте есть файл `api-tests.http`, в котором уже есть примеры запросов к API. Вы можете использовать его для тестирования приложения. Также можно использовать Postman или любой другой HTTP клиент для тестирования API.
Дополнительно к уже перечисленным ручкам, в проекте есть дополнительные ручки для тестирования приложения:
- Endpoint 8: `GET http://localhost:8080/api/access/premium`
  - Эта ручка предназначена для тестирования доступа к ресурсам premium пользователя. Она доступна только для пользователей с ролью premium_user. Если на нее будет отправлен токен с ролью guest, то ручка вернет ошибку 401 Unauthorized.
- Endpoint 9: `GET http://localhost:8080/api/access/admin`
  - Эта ручка предназначена для тестирования доступа к ресурсам администратора. Она доступна только для пользователей с ролью admin. Если на нее будет отправлен токен с ролью guest или premium_user, то ручка вернет ошибку 401 Unauthorized.
